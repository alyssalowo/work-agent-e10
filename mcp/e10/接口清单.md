# E10 MCP 接口清单

来源：2026-10-30 当前服务源码。正式参数以连接后的 schema 为准；prepare/commit 工具受原业务授权和回执约束。

## `e10_manual_catalog`

```python
e10_manual_catalog()
```

列出绑定的包装计划、工单和领料五份原手册及项目交接补充资料、来源校验及可用截图数量。请购资料已排除；无需登录E10。

## `e10_search_manual`

```python
e10_search_manual(query: str, max_results: int=8)
```

按中文关键词检索包装计划/工单/领料说明，返回原文段落号、上下文及截图ID；不搜索请购模块，不执行文档步骤。

## `e10_read_manual`

```python
e10_read_manual(manual_id: str, start_block: int=1, count: int=20)
```

读取手册原文与图片引用；manual_id=integration-guide可读MCP对应规则、资料差异和能力限制。段落按原编号，最多50段，next_start_block供继续读取。无需登录。

## `e10_manual_image`

```python
e10_manual_image(manual_id: str, image_id: str)
```

读取检索结果中的指定手册截图，直接返回图片供查看红框及界面字段。只允许资料库内已登记图片，无需登录，不操作客户端。

## `e10_connection_status`

```python
e10_connection_status()
```

检查大寰公司 E10 连接、当前会话认证状态和本机账号是否已配置；不会尝试登录。

## `e10_login`

```python
e10_login()
```

用本机加密保存的 E10 账号密码登录大寰公司。只尝试一次，返回认证结果，不修改业务单据。

## `e10_current_user`

```python
e10_current_user()
```

读取本 MCP 已登录会话的用户名、显示名和语言；未登录时返回未登录状态。

## `e10_logout`

```python
e10_logout()
```

退出本 MCP 创建的 E10 会话，不退出用户正在使用的 E10 客户端。

## `e10_module_access`

```python
e10_module_access()
```

读取四个生产模块的账号权限和生成模块预览能力；权限不代表已验证写入成功。

## `e10_query_workorder`

```python
e10_query_workorder(workorder_no: str)
```

按完整工单号精确查询维护工单，返回品号、特征码、预计产量、需求单号等；不修改单据。

## `e10_query_picking_requests`

```python
e10_query_picking_requests(workorder_no: str, max_rows: int=100)
```

按完整工单号精确查询关联领料申请单明细、仓库和申请数量。上限1至500；has_next_page表示结果未完整。

## `e10_preview_picking_request`

```python
e10_preview_picking_request(workorder_no: str)
```

预览工单产生领料申请单的候选工单，使用工单实际工厂、产品、性质及客户端默认领料方式1、领料对象工单。只调用GetPreviewData，不生成单据。零候选不代表所有方式均不能领料。

## `e10_get_document`

```python
e10_get_document(module: Literal['MO', 'ISSUE_RECEIPT_REQ'], document_no: str)
```

读取维护工单或维护领料申请单的完整单头、明细、审核状态和版本。MO=工单，ISSUE_RECEIPT_REQ=领料申请单。

## `e10_document_schema`

```python
e10_document_schema(module: Literal['MO', 'ISSUE_RECEIPT_REQ'])
```

读取模块字段类型和可写明细结构，使用未保存的内存对象；不会产生 E10 草稿单据。

## `e10_lookup_master`

```python
e10_lookup_master(kind: Literal['ITEM', 'PLANT', 'DOC', 'WORK_CENTER', 'WAREHOUSE', 'EMPLOYEE', 'ADMIN_UNIT', 'UNIT', 'SUPPLIER', 'PROJECT'], code: str)
```

按完整基础资料编码查询系统ID和名称，供准备单据时使用，避免向用户索要GUID或猜测ID。只有unique=true才可自动采用；多条结果需按实际资料区分。

## `e10_lookup_item_feature`

```python
e10_lookup_item_feature(item_code: str, feature_code: str='')
```

按完整品号及特征码精确查询。验证特征码属于该品号，保留大小写；无特征码产品用空串。只读，不保存。

## `e10_preview_manual_workorder`

```python
e10_preview_manual_workorder(item_code: str, plant_id: str, quantity: float, doc_date: str, start_date: str, complete_date: str, feature_code: str='')
```

只读预览1-成品的手工包装工单：查询当前品号、特征码、工厂、BOM版次，通过原生DoBomExtract展开子件及仓库。日期格式yyyy-MM-dd；不保存、不审核、不取正式编号。

## `e10_prepare_manual_workorder`

```python
e10_prepare_manual_workorder(item_code: str, plant_id: str, quantity: float, doc_date: str, start_date: str, complete_date: str, reference: str, feature_code: str='')
```

准备1-成品的5101包装工单，按当前主数据和原生BOM完整展开子件与仓库，检查特征码、重复单据及BOM完整性。reference写本次包装计划和原始借出单号。未保存、不审核；返回operation_id后由e10_commit_operation正式保存。

## `e10_prepare_document`

```python
e10_prepare_document(module: Literal['MO', 'ISSUE_RECEIPT_REQ'], action: Literal['create', 'update', 'confirm'], document_no: str='', fields: dict | None=None, line_changes: list[dict] | None=None)
```

准备新增、修改或审核，返回未保存的内存草稿与 operation_id。create不填写单号；引用字段用已确认GUID；Owner_Org/SOURCE_ID用{RTK,ROid}。明细格式{collection,action:add/update,row_id:更新时必填,fields:{...}}。confirm不带字段。已审核单据不允许直接修改。字段校验通过不代表实际保存已验证；完整业务校验由正式保存接口执行。

## `e10_query_packaging_workorders`

```python
e10_query_packaging_workorders(date_from: str, doc_no_prefix: str='5101-', start_row: int=1, max_rows: int=1000)
```

包装工单匹配源稳定分页：单号以5101-开头、单据日期含起日、审核不等于V作废、状态不等于y指定完工及Y已完工，全部AND。返回需求单号、品号、特征码和预计产量，不加生管人员或工厂限制。不导出、不写入；按next_start_row读至has_next_page=false。

## `e10_query_workorder_workflow`

```python
e10_query_workorder_workflow(planner_name: str, doc_type_code: str='5101', approval_status: Literal['N', 'Y', 'V']='N', doc_date: str='', start_row: int=1, max_rows: int=500)
```

按完整生管姓名、包装工单单别、审核状态及单据日期AND查询；doc_date空值固定为当前北京时间日期。

## `e10_prepare_workorder_confirmation_batch`

```python
e10_prepare_workorder_confirmation_batch(expected_items: list[dict], planner_name: str='朱浩龙', doc_type_code: str='5101', doc_date: str='', selection_scope: Literal['planner_pending', 'generated_only', 'continuation']='planner_pending', selected_ids: list[str] | None=None, excluded_ids: list[str] | None=None)
```

冻结指定doc_date的朱浩龙/5101/N完整清单并准备一次批量审核；空doc_date固定为当前北京时间日期。

## `e10_query_order_workorder_sources`

```python
e10_query_order_workorder_sources(plant_name: str, date_from: str, excluded_sales_departments: list[str], excluded_order_tokens: list[str], start_row: int=1, max_rows: int=500)
```

按订单产生工单模块原生订单选择器分页查询。完整工厂名唯一匹配；单据日期含起日yyyy-MM-dd、排除完整销售部门、订单单号不包含单别连字符（例如2319-）按AND组合。保留原生已审核、未结束及交货工厂条件，返回实际订单号与稳定分页位置，不生成单据。

## `e10_query_workorder_item_date`

```python
e10_query_workorder_item_date(plant_name: str, doc_type_code: str, item_codes: list[str], doc_date: str)
```

按完整工厂名、单据类型编码、1至50个完整品号及单据日期yyyy-MM-dd精确查询工单单头，返回实际单号、需求单号、数量、创建人及时间，用于按范围查询和异常结果核对。只读；has_next_page为真时不能视为完整。

## `e10_query_order_versions`

```python
e10_query_order_versions(order_nos: list[str])
```

Read current header versions and approval/close states for 1-50 exact order numbers. No preparation or business writes.

## `e10_query_order_workorder_result`

```python
e10_query_order_workorder_result(source_ids: list[str])
```

按已核对的订单子明细GUID查询实际关联工单和单头创建时间等字段，供生成结果归因、超时恢复使用。只读，无自动重试或生成；至多100个来源ID，返回完整性标记。

## `e10_prepare_packaging_order_batch`

```python
e10_prepare_packaging_order_batch(order_nos: list[str], plant_name: str, doc_type_code: str, excluded_1_v_name_keywords: list[str], excluded_1_h_name_keywords: list[str])
```

准备已查询核对的1至50个订单产生包装工单：使用指定单别方式2与当前包装工单类型，仅保留1-成品，1-V及1-H按各自品名排除词筛选。不合并不同订单/客户，不重复产生已抛转未指定完工工单，自动审核关闭。返回完整选中和排除清单及未保存operation_id。提交前核对订单版本与关联工单集合，提交后返回实际新增工单。正式生成另用e10_commit_operation。

## `e10_prepare_order_workorders`

```python
e10_prepare_order_workorders(order_no: str, plant_id: str, options: dict | None=None, selected_ids: list[str] | None=None)
```

订单产生工单向导。先以完整订单号和工厂GUID取候选；未传selected_ids时只返回候选。选定候选ID后准备未保存操作，默认不自动审核。options支持DOC_DATE、DOC_ID、DOC_DEFAULT_TYPE、Owner_Emp、Owner_Dept及合并/损耗选项。不会调用DoProcess生成工单。

## `e10_prepare_picking_generation`

```python
e10_prepare_picking_generation(workorder_no: str, options: dict | None=None)
```

准备工单产生领料申请单，精确预览该工单并返回未保存操作。正式生成需指定NEW_DOC_ID、EMPLOYEE_ID、ADMIN_UNIT_ID、WORK_CENTER_SUPPLIER_ID_NEW的GUID；可指定申请日期、仓库来源/仓库、批号、分单选项。最终行为按所选单据类型业务规则执行，此工具不调用Process。

## `e10_resolve_picking_applicant`

```python
e10_resolve_picking_applicant(applicant_name: str='', apply_date: str='')
```

按完整员工姓名唯一解析领料申请人，空姓名使用当前账号关联员工。按申请日期yyyy-MM-dd（空为今天）核对EMPLOYEE_D内唯一有效主部门；返回EMPLOYEE_ID、ADMIN_UNIT_ID及完整employee资料，不使用登录名或Owner_Dept猜测。

## `e10_query_picking_workflow`

```python
e10_query_picking_workflow(applicant_name: str='', approval_status: Literal['', 'N', 'Y', 'V']='', date_from: str='', detail_close: Literal['', '0', '1', '2']='', workorder_no: str='', workorder_nos: list[str] | None=None, include_detail: bool=True, start_row: int=1, max_rows: int=1000)
```

领料申请单稳定分页查询，至少明确指定一个筛选条件。完整员工姓名、审核状态N/Y/V、含起日yyyy-MM-dd、明细结束码0/1/2、完整工单号或1至500个完整workorder_nos列表按AND组合；两种工单过滤互斥，列表必须去重且非空；结束码与工单均过滤单身。单头按ID去重，明细按ID+DETAIL_ID排序。返回原filters、next_start_row、has_next_page；并发ERP变动时需重新收集，不能把部分分页视为完整。

## `e10_prepare_picking_batch`

```python
e10_prepare_picking_batch(workorder_nos: list[str], options: dict | None=None)
```

准备1至200个去重完整工单的领料申请批次；同批必须同实际工厂、工作中心/供应商。options需当前NEW_DOC_ID、EMPLOYEE_ID、ADMIN_UNIT_ID，可带APPLY_DATE/APPLY_TRANSACTION_DATE、SOURCE_DIFF/WAREHOUSE_DIFF等选项；工作中心默认取工单实际来源，核对申请日有效主部门。返回完整candidates及excluded_workorders；candidate_count不是生成单数。只预览与保存内存操作，正式生成另用e10_commit_operation；operation_id限同一登录会话30分钟。

## `e10_inspect_production_return`

```python
e10_inspect_production_return(workorder_no: str)
```

按完整工单号检查工单、领退料历史、退料单类型及当前操作人员，不生成或保存单据。只有本次用户明确指定退料业务时才进入退料流程。

## `e10_prepare_production_return`

```python
e10_prepare_production_return(workorder_no: str)
```

准备指定工单的全部已领料退回，走标准新增退料单路径：要求工单已审核且无完工/报废/损耗、无有效退料单、审核领料量与已领量及原仓一致，生产退料单类型唯一且不自动审核。返回材料、数量、仓库与未保存operation_id；提交时才取正式单号并SaveAndReturn。部分退料、复杂耗用、单位换算或附加批号/序列号子明细暂不支持；只在用户明确指定退料时使用。

## `e10_commit_operation`

```python
e10_commit_operation(operation_id: str)
```

正式执行已准备的保存、修改、审核或生成操作。会写入大寰公司E10，必须已经取得用户对具体单据和内容的指令。每个operation_id只执行一次；超时或unknown必须先核对实际结果，禁止自动重试或重建草稿重复提交。

## `e10_discard_operation`

```python
e10_discard_operation(operation_id: str)
```

丢弃尚未执行的内存操作草稿。不会删除E10中已保存的业务单据；started/unknown操作必须先核对实际结果。

## `e10_operation_status`

```python
e10_operation_status(operation_id: str)
```

读取内存草稿或本机执行记录，支持在连接重启后核对结果；不会重新执行操作。

## `e10_shipment_query_configuration`

```python
e10_shipment_query_configuration(module: Literal['SALES_DELIVERY', 'BORROW_DOC', 'STOCK_REQUISITION'])
```

读取销货/借出/出库申请当前保存查询视图及字段。借出固定LEND_DOC方向，不套用借入视图；出库申请模块为STOCK_REQUISITION。只读，不保存。

## `e10_query_shipment_details`

```python
e10_query_shipment_details(module: Literal['SALES_DELIVERY', 'BORROW_DOC', 'STOCK_REQUISITION'], fields: list[dict[str, str]], expected_from: str, expected_path: str, status_path: str='', status_end: str='', start_row: int=1, max_rows: int=500)
```

只读销货/借出/出库申请完整原始明细，单据日期从2026-01-01、预计出货日期含起日；按单头和明细ID稳定分页，以has_next_page续页。不在接口中过滤产品或借出结束明细，保留整单标签判断依据。销货须传实际ISSUED_STATUS及出库结束码3；借出禁止套用该状态，须返回CLOSE供本地筛选。出库申请仅包含1018/1008/1012单号前缀，禁止套用销货状态，日期及申请人员路径须从当前配置确认。字段必须包含HEAD_ID/DETAIL_ID/DOC_NO/DOC_DATE及预计日期；创建人来自真实用户资料。
