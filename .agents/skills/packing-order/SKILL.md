# packing order

默认按下列五步连续完成；明确限定阶段时只做该范围，接续按真实回执跳过已完成部分。修改或验证技能只处理本地文件，不执行业务。用户中途询问进度时简短答复后继续已授权任务。

## 五步流程与按需阅读

首次接手相关包装业务，按项目要求用 `e10_read_manual(manual_id="integration-guide")` 读取当前接口对照。随后只读当前阶段必要规则；已读且未变则复用。固定助手直接运行，接口变化或具体错误时才查源码。

| 顺序 | 任务和进入下一阶段的条件 | 规则正文 |
| --- | --- | --- |
| 1 | 销货/借出/出库申请填写；追加明确成功或完整筛选明确零新增后交接指定表完整快照；缺表、范围外和异常单列 | [填写技能及整轮交接](references/shipment-sheet-fill.md) |
| 2 | 订单产生工单和手工产生工单均成功创建（含零新增），再收集完整待审集合统一审核 | [双分支控制器](references/workorder-branches.md)；[订单条件](references/order-workorders.md)；有手工来源再读[业务规则](references/manual19-workorders.md)及[输入](references/manual19-runner.md) |
| 3 | 审核成功后取得包含合规历史工单的完整匹配源 | [工单筛选](references/workorder-filter.md)；[本地分页转换](references/local-review.md#筛选分页与匹配源) |
| 4 | 全部指定表完整匹配，核对计划后回填；手工来源使用实际审核bindings | [工单匹配规则](../packaging-workorder-match/SKILL.md#匹配和分配规则)与其离线batch流程 |
| 5 | 所需非排除行正确对应且有实际审核Y后，提取空白行工单生成领料，再审核、取得完整源并回填 | [后续阶段](references/downstream-stages.md)；[领料匹配规则](../packaging-picking-match/SKILL.md)；[领料接口](references/e10-workflow.md)按需查 |

默认参数各维护一处：订单条件见订单页，统一审核默认 `planner_pending` 及日期冻结见控制器，手工主资料回退见手工来源规则。填写排除 `S263/S630` 与开工单排除 `S263/L630` 是两个阶段的现行条件，不相互替换。

## 工单来源分类

以指定包装计划实际“单号”列的开头判定产生方式，两类使用相同的成品范围、已确认排除及后续审核门槛：

| 产生方式 | 来源单号 | 操作方式 |
| --- | --- | --- |
| 手工产生工单 | 以 `19`、`1018`、`1008`、`1012` 任一值开头 | 在“维护工单”中按包装计划每行逐单新建；出库申请单与其他手工来源执行同一套规则 |
| 订单产生工单 | 其余非空且有效的单号 | 经过“订单产生工单”模块，按本技能的订单筛选与排除条件批量生成 |

分类不代替业务条件；已有工单不重复创建，明确排除项继续保留原值。空白或无效单号列为异常，不猜测产生方式。两类创建完成后统一审核，再筛选、匹配回填及生成领料。

## 阶段接续

每完成上述一个步骤，进入下一步前更新接续信息；明确拆开的创建、审核、生成、查询、匹配回填阶段也在完成后保存。同一完成边界只保存一次，不按每次接口调用重复处理。零新增但已完整核验成功的步骤同样处理。

- 优先按[自动接续检查](references/local-review.md#阶段接续与确定性检查)从原始回执生成本轮 `context-handoff.md`；已有原控制器完整结果直接引用，不另建同义审计。保留最新有效状态：用户最新授权范围和排除决定、已完成步骤及真实计数、当前快照/计划/回执/检查点路径与已有哈希、未解决异常、下一步及其进入门槛。记录持续会话的终端ID、MCP会话ID和必要operation_id/状态，不记录凭据。
- 接续文件只保留接续所需规则和文件索引，不携带整表、完整接口正文或重复成功日志。原始证据仍保存在原文件；摘要不替代回执、审核Y、BOM或版本校验。
- 接续或恢复执行时，先读取 `context-handoff.md` 并按实际操作状态继续，不因恢复而重启E10会话、重读全表、重复正式写入或要求用户重新授权已有业务。
- 异常中断时也保存最新摘要及失败/unknown/in_flight状态，但不得标作步骤完成；原停止、核实和恢复规则继续适用，失败或状态未知的业务仍停止依赖写入。

## 共用契约

- E10 用[持续会话](references/mcp-session.md)，整轮一个会话、业务串行；工单阶段只走 `job=workorders` 控制器。
- 领料申请只能通过“工单管理 → 工单发料 → 工单产生领料申请单”（MO_B012）生成，禁止直接新增领料申请单替代。必须勾选“源单不同”“仓库不同”；参数及提交前核对要求见[领料生成参数](references/e10-workflow.md#生成参数)。
- 第1步先枚举全部工作表。独立填写优先仅读各表完整“单号”列；完整流程对明确需要后续匹配的目标表一次完整采集，其他表仅读单号列（含非日期表）。真实采集与同轮缓存校验通过[按需读取入口](references/sheet-read-plan.md)执行，列级数据不能替代业务快照。
- 钉钉读取、快照和提交只按[官方 MCP 契约](references/dingtalk-mcp.md)。正常首轮采齐、后续用成功回执投影，不因转阶段重读；追加行另按第1步交接。
- 模型与任务职责、工具边界及委派规则统一见[模型与subagent分工](references/subagents.md)。主代理负责ERP、范围/规则、恢复及阶段放行；Terra的钉钉live write默认关闭，须受限入口隔离验收后才开放；Luna无正式写权限。固定程序已有完整校验时不对正常计划做二次逐行模型审计。
- 两分支创建、统一审核及所需行对应的门槛均要通过；部分成功、缺字段、缺回执、unknown不能越过依赖关系。ready/摘要不能代替真实业务证据。

## 停止与交付

单次调用或无实质进展达到180秒即暂停调度并通知用户；失败、unknown/in_flight停依赖写入。完整的等待、证据保存和恢复规则统一见[执行约定](references/performance.md)，不重放未知操作。

按实际回执及原report交付填写数量、各阶段创建/审核/回填计数和全部异常及原值保留原因。提示历史由主代理运行原report更新；不另起同义汇总。结束时显式logout并退出临时MCP会话。
