# 执行、输出与计时

本页是等待、通用失败处理及输出预算的正文。各阶段只补充自己的门槛、检查点和恢复参数。修改文档或离线验证不登录、不写正式业务。

## 正常调度

按阶段加载规则和本轮缓存的 capabilities，不重复枚举或扫描历史。固定助手一次覆盖完整授权范围；本地转换、原程序校验、prepare和异常摘要可顺序合并，任一步失败即停。正式准备、主代理核对和提交分开，依赖写入不预先排队，同一E10会话不并发。

不通过减少分页、抽样、缩小授权集合、跳过原audit/版本/BOM/防重门槛提速。明确零新增直接进入下一合法阶段，不启动空代理或追加确认。表格复用和写前检查只在[钉钉契约](dingtalk-mcp.md#快照生命周期)维护。

## 输出预算

- 完整输入、分页、计划、audit和回执落盘；模型只接收状态、完整性、计数、全部异常类型和产物路径。通常每阶段一条短摘要。哈希从真实文件读取和验证，不手抄长值。
- SessionOutput 保存全部结果，终端只输出白名单摘要。read_sequence 的 summary 用于选择必要原文，不能代替来源、完整校验或业务授权。
- 普通进度最多每30秒一次；失败、unknown、in_flight及最终结果立即输出。进度原文全部保存。正常只等待同一终端，不同时轮询终端、进度文件和逐单回执；异常才定点取证。
- 大表用固定执行器按实际UTF8参数预算落盘，不打印整表、截断、抽样或临时重写传递程序。具体分块与partial规则见钉钉契约。
- 本地交付合并同类工作，异常仅展开受影响字段；原校验已覆盖的正常行不重新逐行核算。

## 停止与恢复

启动长操作记录开始时间，每次等待不超过30秒。**任一调用180秒未返回，或步骤连续180秒没有实际对象、分页或明确检查点完成，立即暂停后续调度并通知用户。** 心跳不重置计时。

通知说明步骤/对象、等待时长、已完成范围、结果是否确定、日志/检查点位置和需要协助的事项。暂停后等待用户明确指示；请求不能取消时只暂停后续调度，不声称远端已停。

失败、超时、中断、unknown/in_flight时保留started、操作ID、检查点及原回执，停止依赖写入。先查操作状态和受影响实际单据/表格范围，区分成功、失败、未知和未尝试项；不自动重试、删除标记、换编号/reference或换目录绕过保护。确认未完成且原因已修复后，才按对应阶段的显式恢复入口接续未完成对象；未知操作不重交，成功对象不重建。

表格异常只补查必要范围；影响重复组或身份时更新该表完整计划。正常提交按实际回执报告，不读回、刷新或运行verify。不关闭用户客户端，不为恢复擅改全局MCP配置。

## 度量边界

比较相同范围、筛选、阶段和时间窗。workflow-timing的命令耗时与mcp-calls的SDK耗时有重叠，不相加；命令间隔还包括本地程序、用户、子代理和其他工具，不能直接归因于模型或ERP。

字符/UTF8字节减少仅证明文本负载减少，无实际token计量不报告token节省百分比；离线验证不证明线上整轮加速，不用正式业务测速。

## 可选性能记录

`mcp_session.py --profile-local` 默认关闭。开启后在本轮目录追加 `local-performance.jsonl`，每条只有固定标签、会话/命令序号及数字；不保存凭据、业务内容、命令参数或文件路径。路径只在当前计量上下文内用于计数，结束清空。不要把完整 JSONL 送给模型；正常仍返回业务状态、计数、异常和产物路径。

- `scope=local_preflight`：本地预检耗时；现有身份检查子进程的调用数和启动至退出总耗时。子进程参数与输出不进入性能日志。
- `scope=server_ready`：现有 E10 Python 子进程启动至 MCP 初始化成功的总耗时和启动次数；包括传输及初始化，不是纯操作系统进程创建时间。启动失败沿用原异常，本条成功就绪记录可能不存在。不为测速增加 Python/JavaScript 子进程。
- `scope=command`：从读取命令到保存/输出结果的总耗时，按 `session_id` 和 `command_sequence` 对应阶段日志。记录已接入公共助手的文件读写次数/字节/耗时、同一路径重复读取次数/字节、SHA256 次数/字节/耗时、JSON 解析/序列化耗时、MCP 调用数与等待、终端摘要 UTF8 字节。

Python 使用 `perf_counter`。此处是公共读写助手的观测，不是全进程文件系统跟踪；未迁移的内联读写、MCP 服务器内部、外部工具和宿主启动均不在本地计数中。`file_reads` 以一次打开并读完文件计数，流式块数不冒充文件数；重复读取按当前阶段路径计数，不判断两次内容是否相同。SHA 耗时与读取耗时分开记录，阶段耗时包含二者及 MCP 等待，不再相加。`subprocess_seconds` 是子进程调用全过程，不能与纯启动延迟混用；为零仅表示该范围未调用已接入的子进程助手。

钉钉执行器在原回执内记录 UTC 时间点和实际调用等待；提供 `performance.now()` 的宿主使用单调时钟，`timing_clock=monotonic`。未提供时写 `elapsed_seconds=null`、`timing_clock=unavailable`，不伪造零耗时，也不让可选计时阻止业务。缺失值不参与延迟统计。

统一开单的验证快照只在一次连续同步检查中有效，解析使用同一份已校验字节，首次外部等待前释放。独立入口、正式执行、跨进程、审核、来源变化与 unknown 恢复仍重新核验；禁止按大小、mtime 或旧哈希放行。文件内容变化后再次调用入口必须重新验证，禁止把内部快照当作跨阶段缓存。

后续先从正常授权任务中采集同范围样本，区分本地处理、MCP 等待、命令间等待与宿主开销，再决定是否扩大优化范围。任务实际 Codex 用量继续按 [usage-comparison.md](usage-comparison.md) 记录；本地字节或哈希次数不能换算成推理 Token。
