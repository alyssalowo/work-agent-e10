# 本地 subagent 分工

可独立交付的批量整理默认委派，不等待用户再次要求。主代理负责范围与授权、E10和钉钉表格MCP、正式写入、共享状态、异常处置及最终放行；子代理仅用只读输入运行固定本地助手，不替主代理做业务决定。

## 模型与批次

| 任务 | 模型/强度 | 交付 |
| --- | --- | --- |
| 字段提取、格式转换、计数、最终报告汇总 | gpt-6-luna / low | 合并本阶段同类任务；领料用 workflow_data.py orders/source，报告只读已完成报告与回执。 |
| 完整筛选分页校验与源整理 | gpt-6-luna / medium | local_review.py workorders，保留全部页及原筛选条件。 |
| 工单/领料离线匹配、重复组及异常整理 | gpt-6-luna / medium | 对应匹配技能 batch.py prepare，一次覆盖全部指定表并保留原全量audit。 |
| 双来源本地计划、领料前逐行对应及审核Y证据 | gpt-6-luna / medium | 完整行级范围、原字段比较、真实回执和用户排除依据；缺门槛即blocked。 |

单条短命令、零新增分支、少量参数及依赖主代理当前操作的步骤直接完成；不为这些碎片启动代理。两来源均有实质本地准备时才并行两个代理；其余通常复用一个。已有medium代理可顺带完成后续简单整理，不仅为降至low新建代理或重跑任务。

并行只用于输入独立的工作，例如子代理转换已齐备ERP分页，主代理用MCP采集目标；输入未齐备不提前启动后等待。正式业务及同一MCP会话保持串行。

## 启动与任务说明

首次使用宿主subagent工具，按表选强度，设 fork_turns=none，避免继承整段业务聊天。例如：

```json
{"task_name":"packing_data","model":"gpt-6-luna","reasoning_effort":"low","fork_turns":"none","message":"仅做本轮指定的本地批量任务。输入只读；运行给定固定助手，产物写指定新目录。禁止在线MCP、凭据、共享状态及业务提交。返回状态、计数、异常与产物路径；完整证据落盘。具体输入和命令见任务文件。"}
```

主代理一次提供当前阶段、全部指定表/范围、实际解释器与脚本路径、确切输入及SHA256、专用输出目录和预期产物。仅传必要规则，不让子代理重读全部skill、历史对话或大业务文件来猜范围。已存在的完整产物直接交付，不要求重建。

任务合并为“转换+原程序校验+异常清单+摘要”；能在同一批次完成的不拆成多个代理或多轮对话。后续复用原代理并给新阶段确切输入，不沿用旧参数。初次委派时简短告知用户；实际未启动不得声称已委派。宿主无法使用指定模型/子代理时主代理继续固定助手并说明，不改全局配置。

## 产物与边界

- 输入只读，输出限独立新目录；已有结果不覆盖。两个代理不共享可写目录。不调用在线MCP、不生成提交规格、不读凭据、不扫描历史、不继续创建代理。
- 原程序已有audit/完整性检查就直接使用，不另写同规则全量审计，不再让另一个代理重复审核同一正常计划。发现原校验未覆盖的业务门槛或具体异常，才定点补证据；不把全量检查改为抽样或让模型重算精确匹配。
- 正常返回约200中文字：task_id、ready/blocked/failed、计数、完整异常类型/阻塞原因及产物清单路径。完整哈希、行级证据按[输出预算](performance.md#输出预算)落盘，不回传整表或长JSON。
- 领料 batch.py report、record-submitted/processed、remember-markers 会写提示历史，必须由主代理执行。子代理只汇总主代理已生成的报告；prepare可只读实际状态文件，或使用主代理给定的状态副本，不写回共享状态。
- 如用状态副本规划，主代理在submit-spec前核对实际同文档状态及变化，确保batch和各plan绑定实际状态路径；不能把副本当共享历史。只改绑定时保留前后哈希；号码/候选未变不重跑匹配，真实历史变化按原助手规则处理。

## 主代理接收与放行

主代理只做一次接收检查：任务/输入/输出身份、输入与产物哈希、固定程序成功回执、原audit与候选完整性、全部指定表覆盖、关键计数及完整异常清单。原程序覆盖的正常结果无需再逐行展开或重算；失败、缺文件、哈希变化及新增异常先处理。

ready仅表示本地任务完成。工单逐行对应、实际审核Y、完整分页、用户排除依据及正式业务回执仍须具备；缺少字段比较、范围或非排除行实际Y时blocked。证据索引命令见[local-review.md](local-review.md)，仅在现有产物不能直接定位所需证据时使用，不为每个阶段机械新增索引。

不重复采集来验收子代理，不重跑已有完整prepare。写前由主代理按[钉钉快照契约](dingtalk-mcp.md#快照生命周期)检查，不要求子代理另取线上快照；通用异常与恢复见[执行约定](performance.md#停止与恢复)。
