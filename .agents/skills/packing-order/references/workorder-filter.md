# 审核后、匹配前的包装工单筛选

默认完整流程的顺序：订单来源和手工来源工单全部创建 → 统一审核完成 → 本页筛选 → 工单匹配回填 → 领料。筛选是独立必经阶段；统一审核完成不代表已经取得匹配源。

## 用户截图条件的文字记录

以下五项为用户已确认的当前筛选条件，全部以 **并且（AND）** 连接：

| 字段 | 条件 | 值 | 含义 |
| --- | --- | --- | --- |
| 单号 | 起始于 | `5101-` | 工单单号以5101-开头 |
| 单据日期 | 起始于 | `2026/01/01` | 单据日期大于等于2026-01-01，包含当日 |
| 审核 | 不等于 | `V.作废` | 排除审核状态V的作废工单 |
| 状态码 | 不等于 | `y.指定完工` | 排除状态码小写y的指定完工工单 |
| 状态码 | 不等于 | `Y.已完工` | 排除状态码大写Y的已完工工单 |

保留状态码大小写：`y`和`Y`是两个不同状态，均须排除。日期是用户指定的固定起日，不自动改为执行当日、当月或当年年初；用户当次明确变更时，按新条件执行并记录。

本筛选与“指定生管人员的待审核工单清单”不同。默认查询上述条件下的完整工单集合，包含符合条件的历史工单；不得自行增加生管人员、工厂、仅本轮新增或审核必须等于Y等限制。进入领料前所需工单的对应与实际审核Y证据，仍按原工单阶段门槛另行检查。

## 取得完整匹配源

两类开单及统一审核均有成功回执后，在原MCP会话使用已安装的只读工具 `e10_query_packaging_workorders`：

```json
{"name":"e10_query_packaging_workorders","arguments":{"date_from":"2026-01-01","doc_no_prefix":"5101-","start_row":1,"max_rows":1000}}
```

该工具同时执行审核不等于V、状态不等于y及Y。逐页保存原始结果；按 `next_start_row` 读取至 `has_next_page=false`。核对每页 `ok=true`、五项条件一致、行号连续以及工单ID/单号无重复；分页不完整、条件不符或查询失败时不进入匹配。不能沿用审核前的查询结果，也不能用本轮生成回执或待审核清单代替完整筛选结果。

当前源同时保留真实PLANT_ID、SOURCE_ID、SOURCE_TYPE，供后续领料按工厂及工作中心分组；匹配TSV仍使用下列原业务字段。分组直接复用完整原始源，只补查字段缺失或有变更证据的工单，不再例行逐张取得相同资料。

完整分页可交本地子代理按[本地助手约定](local-review.md)运行 `local_review.py workorders` 校验并转换；有独立读取任务时可并行，各自输入输出隔离；已有完整目标快照不重采。固定程序负责精确条件、分页、数量文本及去重检查，主代理核对产物哈希、完整性和异常后进入匹配。

按下列映射形成原匹配助手可读的完整TSV/CSV源，保存本轮条件、分页和完整性记录，不默认导出XLSX：

| 查询返回字段 | 匹配源表头 |
| --- | --- |
| `DOC_NO` | 单号 |
| `DEMAND_NO` | 需求单号 |
| `ITEM_CODE` | 产品品号 |
| `ITEM_FEATURE_CODE` | 特征码 |
| `PLAN_QTY` | 预计产量 |

随后才按相邻 packaging-workorder-match 的原四字段规则生成并核对完整匹配计划。手工来源以实际审核后的行级bindings对应，并与同轮筛选工单集合核对；不得通过bindings绕过筛选或把缺少需求单号伪造成普通订单来源。筛选外、缺字段或不一致对象保留并报告，沿用用户已确认的排除决定，不擅改旧值。
