# 模型与 subagent 分工

执行packing-order时，主代理使用 gpt-6.1-sol，默认high；负责范围与授权、整体规划、流程调度、复杂操作与分析、证据验收、E10和钉钉表格MCP、正式写入、共享状态、异常处置及最终放行。跨来源矛盾、规则歧义或未知/部分提交需要深入分析时，按需使用xhigh。模型选择以用户当次指定和宿主实际支持为准；本技能不自动切换当前主模型。当前会话不是Sol时说明差异并由当前主代理保留这些职责，不另起Sol子代理替代主控，不修改全局配置。

可独立交付的任务默认按下表委派，不等待用户再次要求：Terra承担中等复杂度的本地准备、多字段核对及证据整理，Luna承担规则清晰的重复批量操作。两类子代理推理强度均以high起步且不得低于high；本技能的强度要求优先于通用分工中的low/medium默认值。子代理只读本轮指定材料，运行固定本地助手或整理证据；复杂判断和业务决定回到Sol主代理。

## 模型与批次

| 任务 | 模型/强度 | 交付 |
| --- | --- | --- |
| 主代理：规划、复杂操作与分析、正式操作及最终核对 | gpt-6.1-sol / high，深入疑难按需xhigh | 承担上述主代理职责，直接处理跨来源矛盾、规则歧义及未知/部分提交恢复。 |
| 字段提取、格式转换、计数、证据索引、最终报告草稿 | gpt-6-luna / high | 合并本阶段同类任务；领料用 workflow_data.py orders/source，报告只读已完成报告与回执，最终交付由主代理确认。 |
| 完整筛选分页校验与源整理 | gpt-6-luna / high | local_review.py workorders，保留全部页及原筛选条件；分页缺失或字段冲突返回完整异常。 |
| 工单/领料离线匹配、重复组及异常整理 | gpt-6.1-terra / high | 对应匹配技能 batch.py prepare，一次覆盖全部指定表并保留原全量audit；精确匹配由固定程序计算，复杂歧义交主代理。 |
| 双来源本地计划、领料前逐行对应及审核Y证据 | gpt-6.1-terra / high | 整理完整行级范围、原字段比较、真实回执和用户排除依据；缺门槛即blocked，最终放行由主代理决定。 |

复杂异常由Sol主代理直接分析，不另设每次提交前的固定二审。未知或部分提交先按[停止与恢复](performance.md#停止与恢复)停止依赖写入，由主代理查询实际状态；不得凭推断宣布成功、授权排除或重试未知操作。Terra任务确需更深入的多表证据整理时可用xhigh；一旦涉及业务规则裁决或恢复决策，交回主代理。Luna默认high；不因任务简单降级，也不因任务量大机械升级。日常不默认使用max或ultra，不因模型升级扩大授权范围。

单条短命令、零新增分支、少量参数及依赖主代理当前操作的步骤直接完成；不为这些碎片启动代理。两来源均有实质本地准备时才并行两个批量代理；其余优先复用承担同类任务的Terra或Luna代理。已有Terra代理可顺带完成后续简单整理，不仅为换成Luna新建代理或重跑任务。Luna遇到超出既定规则的多字段歧义时保留现有产物交主代理，主代理只将必要的证据整理部分转交Terra，避免重跑已完成批次。

并行只用于输入独立的工作，例如子代理转换已齐备ERP分页，主代理用MCP采集目标；输入未齐备不提前启动后等待。正式业务及同一MCP会话保持串行。

## 启动与任务说明

首次使用宿主subagent工具，按表显式指定子代理模型和强度，设 fork_turns=none，避免继承主代理模型及整段业务聊天。启动和复用时均确保reasoning_effort不低于high；已有低强度代理不能直接沿用本技能任务，须用宿主支持的方式提升强度，否则新建符合要求的代理。例如：

```json
{"task_name":"packing_data","model":"gpt-6-luna","reasoning_effort":"high","fork_turns":"none","message":"仅做本轮指定的本地批量任务。输入只读；运行给定固定助手，产物写指定新目录。禁止在线MCP、凭据、共享状态及业务提交。返回状态、计数、异常与产物路径；完整证据落盘。具体输入和命令见任务文件。"}
```

多字段匹配准备或审核证据整理改用 model=gpt-6.1-terra、reasoning_effort=high，确需升级时用xhigh。任务说明限定具体核对问题、允许读取的材料和固定助手，要求区分已证实事实、假设及缺失证据。其产物仍是本地计划或证据清单，不是业务提交或放行回执。

主代理一次提供当前阶段、全部指定表/范围、实际解释器与脚本路径、确切输入及SHA256、专用输出目录和预期产物。仅传必要规则，不让子代理重读全部skill、历史对话或大业务文件来猜范围。已存在的完整产物直接交付，不要求重建。

任务合并为“转换+原程序校验+异常清单+摘要”；能在同一批次完成的不拆成多个代理或多轮对话。后续复用原代理并给新阶段确切输入，不沿用旧参数。初次委派时简短告知用户；实际未启动不得声称已委派。调用前核对宿主支持的模型及强度；指定模型不可用时由主代理继续固定助手并说明，或选择宿主支持且适合该任务的另一子代理，强度仍不得低于high，不改全局配置。

## 产物与边界

- 输入只读，输出限独立新目录；已有结果不覆盖。两个代理不共享可写目录。不调用在线MCP、不生成提交规格、不读凭据、不扫描历史、不继续创建代理。
- 原程序已有audit/完整性检查就直接使用，不另写同规则全量审计，不再让另一个代理重复审核同一正常计划。发现原校验未覆盖的业务门槛或具体异常，才定点补证据；不把全量检查改为抽样或让模型重算精确匹配。
- 正常返回约200中文字：task_id、ready/blocked/failed、计数、完整异常类型/阻塞原因及产物清单路径。完整哈希、行级证据按[输出预算](performance.md#输出预算)落盘，不回传整表或长JSON。
- 领料 batch.py report、record-submitted/processed、remember-markers 会写提示历史，必须由主代理执行。子代理只汇总主代理已生成的报告；prepare可只读实际状态文件，或使用主代理给定的状态副本，不写回共享状态。
- 如用状态副本规划，主代理在submit-spec前核对实际同文档状态及变化，确保batch和各plan绑定实际状态路径；不能把副本当共享历史。只改绑定时保留前后哈希；号码/候选未变不重跑匹配，真实历史变化按原助手规则处理。

## 主代理接收与放行

批量任务由主代理只做一次接收检查：任务/输入/输出身份、输入与产物哈希、固定程序成功回执、原audit与候选完整性、全部指定表覆盖、关键计数及完整异常清单。原程序覆盖的正常结果无需再逐行展开或重算；失败、缺文件、哈希变化及新增异常先处理。Terra交付的核对结果由主代理确认引用的原始证据、未解决项及适用范围，不再让Luna或另一Terra重复全量审计正常计划。

ready仅表示本地任务完成。工单逐行对应、实际审核Y、完整分页、用户排除依据及正式业务回执仍须具备；缺少字段比较、范围或非排除行实际Y时blocked。证据索引命令见[local-review.md](local-review.md)，仅在现有产物不能直接定位所需证据时使用，不为每个阶段机械新增索引。

不重复采集来验收子代理，不重跑已有完整prepare。写前由主代理按[钉钉快照契约](dingtalk-mcp.md#快照生命周期)检查，不要求子代理另取线上快照；通用异常与恢复见[执行约定](performance.md#停止与恢复)。
