# 19 开头来源的包装工单与领料前置检查

此分支属于 packing-order 默认工单阶段。先识别指定工作表中实际“单号”列以19开头的行，不能用“单身来源单号”是否为空代替该条件。准备完整候选并创建工单，本分支不审核；订单分支也完成创建后统一审核，再匹配回填，全部工单阶段完成后才进入领料。

## 来源和对应规则

- 按[钉钉表格MCP](dingtalk-mcp.md)取得本次指定表的完整当前数据，以真实单号、产品品号、完整特征码和每行数量形成行级来源。普通表scope.specs保存真实sheet_id和row；AI表保存record_id及本地投影row，不能伪造普通表recordId或用同值行移动掩盖AI记录身份改变。只使用本次适用的成品范围，不扩展到其他手工工单。
- 对应字段为“销货明细_品号”“销货明细_特征码”“销货明细_业务数量”；按精确值核对，不模糊匹配、不合并行、不四舍五入。特征码空白只有E10确认该品号无特征资料时才能采用；需要特征码而表中缺失时先取得用户确认，不能自行选默认值。用户提供的行级覆盖值单独记录，不擅改表格其他列。
- 相同来源、品号、特征码、数量出现多行时，逐行保留数量并分配不同工单，不把同一工单重复回填给多个行；除非用户明确要求合并。不以“品号相同”认定原工单可以复用。
- 已有工单先实时核对产品、特征码、数量和审核状态。正确既有单据不重开；陌生号码或不一致保持原值并报告，只有用户明确决定后才替换或新增。用户排除的行保留原值，不能继续为该行生成领料或填入不相符的领料号码。

## MCP 准备、开具与审核

默认由双分支控制器调用本节底层流程。只有用户明确限定19来源创建任务时，才可单独使用 [19来源分支调度助手](manual19-runner.md)：先 `manual_prepare`，主代理用本轮初次完整快照核对完整计划及来源后再 `manual_create`，不为该步骤重新在线采集。每行各自准备并正式保存，不审核；默认完整流程的统一审核由双分支控制器执行。助手首错停止，不并发、不自动登录、不自动重试。

1. 沿用当前用户确认的工厂和包装工单类型，实时取得系统ID。单据日期取本次要求，否则用Asia/Shanghai当日；计划开工、完工按表中实际排产日期或用户明确要求，不从旧截图或示例猜日期。
2. 用 `e10_preview_manual_workorder` 核对品号、特征、数量、真实工厂资料、当前BOM及展开子件，再用 `e10_prepare_manual_workorder` 准备未保存草稿。工厂资料中的工作中心、生产部门分别来自 `WORK_CENTER_ID`、`PRODUCTION_ADMIN_UNIT_ID`。已有有效值保持原值；实际工作中心字段缺失或为空时，通过MCP精确查询名称为“生产车间”的当前唯一有效工作中心并填写。实际生产部门字段缺失或为空时，默认通过MCP精确查询名称为“生产部”的当前唯一有效部门，用其真实ID填写待开工单的生产部门，无需再次询问；不修改品号工厂主资料，不用员工所属部门代替。默认项不存在、多条或资料无效时停止，不硬编码其他电脑的ID。预览须保留原主资料、实际采用的部门及默认处理标记；准备与提交检查包含实际工作中心、生产部门及版本。字段映射错误须修正接口，不能当作主资料空缺。
3. reference使用[调度输入](manual19-runner.md#1-形成行级范围)的稳定格式与完整表内序号；不能用本轮随机标识、空白行重新编号或改reference绕过防重。
4. 首次正式保存前核对本分支全部候选及完整BOM，按原版客户端默认规则初始化状态码和工艺管理；当前入口仅支持工艺管理0且路线GUID为空；其他值停止并说明能力缺口，不强填0或自行补路线。确认子件、仓库、数量、日期、工厂及单据类型；重新核实源行关键字段和工单格仍符合准备时范围。随后在同一MCP会话逐个 `e10_commit_operation`，每张保存一次。失败、超时或unknown停止依赖写入，保留原开始标记，先核对实际结果，不换reference或操作号绕过保护。
5. 创建回执和逐行bindings保存完整，等待另一分支完成创建；不得在此处审核。统一审核由双分支控制器执行。

## 避免重复排障与耗时

- 生产部门、工作中心的取值与空缺回退仅按上节第2项；接口须正确映射PRODUCTION_ADMIN_UNIT_ID，不能读不存在的WORK_CENTER.ADMIN_UNIT_ID。接口未支持时先修复验证，不以正式保存测试。
- 原版客户端的新增默认值已落实到连接：初始 `STATUS=1`；本入口仅支持工艺管理0，工艺路线GUID为空。助手在首次正式保存前检查这些字段，不能依靠一次正式保存来发现缺失。其他工艺管理值继续停止，不强填0来绕过工序。
- 审核准备会重新读取单据。版本、树节点、系统日期等可由E10保存后正常补齐，不将整个JSON字节相等作为业务一致条件；产品、特征、产量、日期、生产部门、人员、来源、全部子件/仓库与产出必须逐项一致，提交前仍由服务端校验当前版本。
- 本轮相同产品组预览可复用；每张草稿、子件ID、来源reference、正式单号保持独立。原生提交前的当前BOM/主资料指纹和重复单据复查保留，不能为了速度克隆已保存工单或缓存BOM后跳过复查。
- 输出、进度和等待统一按[执行约定](performance.md)，本分支只补充BOM、身份和来源保护，不逐张在聊天中调度。
- 认证失效只在尚未写入的准备/查询阶段显式恢复；长时间等待后先检查认证。已有 `started`、`unknown` 或 `in_flight` 时先查实际单据，不能因重新登录、重启或新目录而重放。

## 回填与阶段完成条件

19来源可能没有订单向导的需求单号，不伪造“需求单号”或修改真实“单身来源单号”来套四字段规则。普通订单继续用原四字段匹配；19来源按原单号、三字段和行级开单回执对应。合并两类完整计划，按[钉钉表格MCP](dingtalk-mcp.md)写前检查并批量更新实际记录的工单号。19来源的检查额外包含真实单号及recordId；保留其他列及已有值。相同信息的多行必须使用不同的实际工单。

进入领料之前形成可核对的工单阶段完成记录，包含所需行、对应工单、实际产品/特征/数量、审核Y证据、排除行和未解决异常。原始查询、正式回执和完整校验结果必须保存，不能只凭子代理摘要判断。控制器整体creation-gate检查两分支创建完成；本分支最终本地校验只核对19来源行和其实际审核Y，不替代订单分支或审批集合的整体检查。

只有本轮应处理且未被用户排除的工单行全部完成对应、开具和审核，才允许进入领料空白检查、领料生成与审核、号码匹配回填。工单缺失、不匹配、未审核、版本或提交结果未确认时，停止领料阶段并先处理工单问题。已完成阶段依据回执接续，不重复产生或审核；正常表格提交后仍不增加写后读回。
