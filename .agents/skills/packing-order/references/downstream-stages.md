# 工单回填与领料阶段

双来源创建和统一审核完成后，先按[工单筛选](workorder-filter.md)取得完整源。工单匹配、领料分类的正文分别在对应匹配技能；本页仅定义阶段顺序、范围及领料前门槛。表格采集、check-before、提交及本地投影统一见[钉钉契约](dingtalk-mcp.md)，异常按[停止与恢复](performance.md#停止与恢复)。

## 快照与范围

第1步成功追加后的完整快照包含指定表原有行和新增行。工单回填成功后用固定投影助手生成新快照，领料各步骤共用它，不因ERP生成/审核再采表。

| 用途 | 必须覆盖 |
| --- | --- |
| 工单匹配及领料前检查 | 全部指定表的应处理行；用户明确排除行保留身份和原因 |
| 领料生成 | 机器领料单号为空 **OR** 物料领料单号为空的非排除业务行，提取其有效包装工单 |
| 领料明细查询与号码匹配 | 全部指定表非排除工单，包含两列已有领料号的行；不能用上述空白生成集合替代 |

所需非排除行必须正确对应工单，具备产品、特征、精确数量的原字段比较及实际审核Y证据。优先用原计划/audit、当前源及正式回执；只有不能直接定位时才用[证据索引](local-review.md)。缺失、冲突、未审核或结果未知先处理，不凭摘要ready进入领料。

## 1. 工单匹配回填（总流程第4步）

按[工单规则](../../packaging-workorder-match/SKILL.md#匹配和分配规则)规划全部指定表；手工来源另用实际审核后的行级bindings合并计划，并核对同轮完整筛选源，不伪造需求单号。明确排除行保留原值。完整计划核对后提交，用成功回执投影下一阶段快照。

以下属于总流程第5步；单独匹配任务不自动进入生成或审核。

## 2. 提取领料生成工单

运行：

```text
python scripts/workflow_data.py orders --snapshot 本轮工单回填后快照.json --exclusions 本轮生成排除.json --out-dir 新生成清单目录
```

无排除时省略该参数。快照本身只包含本次指定表。助手按上表空白条件取工单；多工单按真实换行或 / 拆分、去首尾空白，按表/行顺序全局去重，以英文 ; 连接。空工单或异常片段单列，不猜号、不部分提取异常格。没有有效工单不生成。

## 3. 生成与审核

按[E10接口](e10-workflow.md#生成参数)取得当前类型、申请人及有效主部门，并遵守唯一生成入口和两项必选分单参数。申请人未指定则核实当前登录人；申请日期未指定则取Asia/Shanghai当日。以实际工厂、工作中心分组，复用完整工单源的PLANT_ID、SOURCE_ID、SOURCE_TYPE，仅补查缺失或已变更对象。

首次提交前核对所有组完整候选和参数，同会话逐组commit。无候选单列；候选工单数不能当成实际申请单张数，新增归因按接口规则核实。

审核先按本次申请人员和状态N采齐完整单头清单，再一次串行调度。要求“所有未审核”时不擅加本轮工单或生成日期；明确“仅本批”才按其范围处理。核对当前Owner_Emp、状态、版本及实际审核日期，已审核记跳过。完成情况按正式回执及必要的ERP查询判断。

## 4. 完整领料源

先用完整快照生成查询请求：

```text
python scripts/workflow_data.py source-request --snapshot 本轮工单回填后快照.json --sheets 本次全部表名逗号分隔 --exclusions 本轮回填排除.json --filters 用户实际筛选.json --out-dir 新查询计划目录
```

无排除或附加筛选时省略对应参数。回填排除须按实际行/身份核实，不照搬生成排除。保留当次日期、人员及明细结束码条件；日期起始含当日，detail_close=0为明细未结束，不替换成单头结束状态，也不私加申请人或类型。

用产出的collect命令查询完整workorder_nos列表，include_detail=true，保留实际filters和全部分页。工具上限及分页字段见[E10接口](e10-workflow.md#明细查询)。列表为空不请求；超上限不截断，schema不支持时报告能力缺口，不删列表改查全公司。

完成查询后：

```text
python scripts/workflow_data.py source --query 完整查询.json --snapshot 本轮工单回填后快照.json --sheets 本次全部表名逗号分隔 --exclusions 本轮回填排除.json --out-dir 新领料源目录
```

助手验证列表精确覆盖目标集合、来源哈希、分页与明细唯一性。服务端列表之外的返回行属于查询异常。目标内审核Y参与，V保留排除证据但不贡献新号码；N、空白或未知返回非零且不输出可用TSV，先完成已授权审核或核实。旧无列表查询的范围外N只保留依据，不审核；旧四字段文件没有状态列时保留兼容，不猜其状态。

## 5. 领料匹配回填

按[领料技能](../../packaging-picking-match/SKILL.md)一次形成完整计划并提交：分类、全部号码合并、旧值和提示历史均由该技能维护。只有用户明确只填空白时设置only_empty。主代理运行原report更新实际submitted提示历史，保留marked/processed；不为汇总另建同义报告。
