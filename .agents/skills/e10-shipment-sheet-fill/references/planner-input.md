# plan.py 现有输入契约

**适用边界**：当前plan.py会强制两模块提供outbound_status，不接受借出明细结束字段，因此不能直接规划现行借出规则。业务规则以[技能正文](../SKILL.md)为准；不为通过校验构造不存在的借出状态。借出用忠实的本轮离线适配，原始数据和筛选依据另存，再与销货子计划合并。

输入JSON必须声明`records_complete: true`、`sheets_complete: true`。只运行销货子计划时，records_complete仅表示传入的销货原始范围完整，不表示借出已规划；整任务仍须两个模块完整读取并核对。sheets_complete表示整本目标文档目录及去重索引齐全，不用布尔值掩盖缺页。`--today`传用户时区确定的查询日，不能默认用执行主机日期。

## records：每个原始明细一条

每条必需字段：

| 字段 | 值 |
| --- | --- |
| module | 当前直接规划用`sales`；`borrow`是旧接口可取值，但不满足现行借出语义 |
| doc_no、detail_id | 完整单号、稳定明细ID |
| doc_date、expected_date | ISO日期YYYY-MM-DD；源时间值先准确转换成业务日期 |
| outbound_status | 销货真实状态元数据转换的`不需出库`、`未出库`、`部分出库`或`出库结束`；借出无此字段，不伪造 |
| doc_type_name | 筛选前的真实单据名称 |
| doc_type_code | 真实单据类型代码；借出单必填，销货单可以为空 |
| item_code、item_name | 当前明细品号、品名 |
| delivery_label | 当前明细的实际交付标签；空值使用空串或null |
| columns | 按真实来源列名整理的值对象；单元格值仅为字符串、数字、布尔值或null |

`columns`保留单头`备注`和明细`销货明细_备注`/`借出明细_备注`两个独立字段。其他来源字段先按已确认的语义映射成目标列名；借出明细前缀可交给脚本转换。源“预计出货日期”对应目标“预计发货日期”，计划器会使用`expected_date`明确填入后者。

计划器从顶层字段填充“单号”“销货明细_品号”“销货明细_品名”“交付标签”“单据类型”和实际预计日期，其他列从`columns`对应。顶层字段与`columns`已有同名字段不一致会报错，避免遮盖源适配错误。`columns`里不要预填箱号、排产日期等没有真实来源的值。

同一单号必须属于同一模块，单头日期、预计日期、出库状态、单据名称/类型代码须一致；冲突会报错，不生成可执行计划。明细ID在模块内必须唯一。

## sheets：整本钉钉文档所有sheet

每项包含：

- `sheet_id`：官方MCP返回的真实ID。
- `name`：真实名称。
- `headers`：按真实列顺序排列的字符串数组，保留空标题及列位置。
- `doc_nos`：该sheet全部非空“单号”值；没有该列时为空数组。
- `date`：已确认的ISO完整日期；非日期sheet使用null。不可把未确认年份的MMDD直接当作固定年份。

单号按去除首尾空白后的完整字符串精确比较，不按前缀或子串去重。非日期sheet也参与去重。重复日期或重复sheetId会报错。

## 输出与执行

- `sheets`：每个待写sheet的`sheet_id`、`name`、`headers`、`values`与逐行`source`。
- `missing`：缺少可用日期sheet的单号、实际预计日、理想目标日、明细ID及数量。
- `excluded_details`、`excluded_documents`：明细级和单据级剔除原因。
- `counts`：输入、已有单号、其他单据过滤、明细过滤、待写、缺表行数和单号数。

该输出是待写计划，不是成功回执。实际填写时使用当次授权的文档链接和官方钉钉MCP；返回values中可能以`=`开头的业务文本时，要用明确的文本单元格写法，不能让表格将其当公式。根据每次正式写入回执另行统计实际完成量。
