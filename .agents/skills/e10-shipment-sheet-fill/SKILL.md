# 销货、借出单据填写

使用中文。使用当次指定的钉钉表格链接；上下文已有链接时沿用。创建或更新本技能只修改技能文件，不因此执行业务填写。

## 数据与接入

- E10模块为“维护销货单”和“维护借出单”。E10操作通过MCP执行，读取当前字段、选项值和用户视图；不通过界面自动化或绕过MCP直接调用客户端业务组件。
- 先核实实际可用的两个模块查询入口。只接入工单/领料查询的连接不等于已支持销货/借出查询；缺少入口时说明具体缺项，不能用其他单据代替，也不能把部分模块结果当作完整结果。
- 使用官方钉钉电子表格MCP，先枚举全部sheet并使用真实sheetId。每个有“单号”列的sheet都参与去重，包括非日期sheet；没有该列的sheet记录名称。
- 完整读取两模块全部分页和同单号全部原始明细；销货标签若来自真实关联字段，读取实际关联值，不用已过滤后的部分明细判断整单。借出单按已确认空标签处理，不推断关联订单标签。
- 查询当天按用户时区Asia/Shanghai确定，并固定在本次运行开始时；不要把2026-10-22写成永久当天。单据日期起点固定为2026-01-01，直到用户另行修改。

## 筛选规则

单据级条件同时满足：

1. 销货单号不以以下任一前缀开头：`2409、2410、2411、2412、2416、2417、2502、2503、2505`。这些前缀限制仅用于销货单。
2. 借出单的真实单据名称既不等于`内部借出单`，也不等于`借料单(工厂用)`。先按原名称筛选，再做输出名称替换。
3. 两模块单据日期不早于2026-01-01。销货单的出库状态不等于`出库结束`，按真实选项元数据确认状态值。借出单没有“出库状态”，不套用销货状态过滤；按下述借出明细结束规则处理。
4. 预计出货日期不早于查询当天；当天保留。
5. 用完整单号与目标文档全部sheet的“单号”列精确比对；任何sheet已有该单号，整单不新增。

以下条件分别只剔除命中的明细，不影响同单号未命中的明细；两类模块均适用：

- 品号以`1-V`开头，且品名包含`S263`或`S630`。
- 品号以`1-H`开头，且品名包含`DSN`。
- 品号以大写`E`开头。

借出单另按真实`借出明细_结束`元数据剔除已结束明细，只剔除明细，不剔除同单号其他保留行。不能把该字段当作销货出库状态。

保留用户提供的大小写和文本匹配方式。先用同单号全部原始明细完成标签判断，再剔除上述明细；即使命中的明细不填写，其标签仍参与整单判断。全部明细都被剔除时，该单不写入。

## 日期与工作表分配

借出单没有“交付标签”，按空值处理，保留明细始终安排在实际预计出货当天；不从来源订单推断标签。以下标签提前规则用于销货单。

优先级如下，不交换顺序：

1. 预计出货日期为查询当天或次日：直接填该出货日期当天的工作表，不看交付标签。例如10/22查询时，10/22和10/23分别填1022、1023；不是包含10/24的三天窗口。
2. 预计出货日期为后天及以后：同单号全部原始明细的交付标签均完整匹配`^[sS][0-9]+$`，则保留明细统一安排到出货日期前一天；只要有一条不匹配（包括空标签），统一安排到出货日期当天。
3. 仅对于第2项中需要提前一天的单据：前一天的工作表不存在时，向前选择最近已有日期工作表。例如10/24出货应填1023，没有1023则填1022。
4. 按当天安排的单据没有当天工作表，或提前安排的单据没有可用的向前日期工作表，暂不填写。汇总预计日期、理想目标日期、单号和剩余明细数量；不自动建表，也不随意改填1022等固定表。

日期sheet通常用MMDD命名。为计划工具提供已确认的完整日期，跨年或重名日期表不能仅凭四位名称猜年份。同单号的单头或预计日期不一致、日期缺失/无效时，列为异常并澄清，不擅自拆单或采用第一行日期。

**工作表分配日期和预计发货日期列是两个值。表内“预计发货日期”始终保留E10实际预计出货日期。**

## 字段与填写

- 按目标表头逐列对应；借出单字段中的`借出明细`对应表格中的`销货明细`，例如`借出明细_品号`→`销货明细_品号`。
- 备注列合并明细备注和单头备注：`销货明细_备注`与`备注`中的非空文本依次用`/`连接；借出单先将`借出明细_备注`归一到`销货明细_备注`。不填入空值占位符，也不自行删除相同文本。
- 借出单输出到“单据类型”列时按真实类型代码替换：`1902`→`送样借出单`，`1904`→`备机借出单`，`1908`→`客户借货单`；其他代码保留其真实名称，不因此额外剔除。
- 创建人姓名须关联真实用户姓名，不能用业务员代替；流程流水号不是产品序列号。缺少对应来源字段的流程列留空，不推断箱号、排产日期、完成状态、包装工单或领料单号。
- 追加新明细，保留原表头和现有行。首次填写前完成全量匹配、去重、标签判断、日期分配和字段映射；不做填写后的全表复核。
- 日期、数量须按真实类型写入：预计发货日期使用日期数值并设置日期格式，销货明细_业务数量使用数值；单号、品号、特征码等保持文本和前导零。不能将所有字段转字符串提交后直接记完成，也不能只改显示格式当作类型转换。普通表可用CSV先保留文本，再仅对日期/数量列明确转换；完整packing-order使用其固定shipment追加执行器。用户已手工修好的数据不自动重写。
- 写入失败、超时或结果未知时，只核查相应操作和目标范围以判断实际结果，不能盲目重复追加。以成功写入回执确认完成。

## 可复用的本地计划器

重复执行可使用[scripts/plan.py](scripts/plan.py)生成销货子计划。**当前脚本仍把outbound_status作为两模块必填字段，尚未支持上述借出明细结束例外，不能直接用于本轮借出规划，也不能伪造状态满足它。** 借出须在本轮离线适配中忠实实施现行规则，并与销货子计划合并核对。它不连接E10或钉钉，也不会执行正式写入。读取[references/planner-input.md](references/planner-input.md)准备归一化数据后运行：

```text
python scripts/plan.py input.json --today YYYY-MM-DD --output plan.json
```

需要源数据适配时，按当前MCP字段/视图确认来源字段和显示值后再归一化；脚本输入约定不代表已安装新的ERP接口。输入要保留将被明细规则剔除的行。计划器输出每sheet的二维values、明细ID、缺表清单及筛选计数；销货子计划不代表整个填写任务已规划完成。两个模块最终按原始明细ID核对全部筛选、缺表、范围外和待写行。

## 结果

报告实际新增单号数、明细数、各sheet行数，已有单号剔除数量、明细剔除数量，以及缺表和异常。默认不导出用户文件；本地计划和回执只用于执行记录。用户当次补充规则优先于本技能。
