# 包装工单匹配

只处理本次明确文档、工作表和字段。先完成全量匹配及修改计划，再提交确定项；不默认导出，不在写后全表读回或刷新。独立调用只做本匹配阶段；由packing-order调用时按它的阶段门槛接续，不在本技能另行生成或审核业务。

## 匹配和分配规则

| 工单 XLSX 字段 | 目标包装表字段 | 处理 |
| --- | --- | --- |
| 需求单号 | 单身来源单号 | 仅源字段按 `-` 从右分割，去掉末尾 **两段及其分隔符**，目标字段保留完整值 |
| 产品品号 | 销货明细_品号 | 精确匹配 |
| 特征码 | 销货明细_特征码 | 精确匹配，空值与空字符串等价 |
| 预计产量 | 销货明细_业务数量 | 按精确数值匹配，例如 `5` 与 `5.0` 等价 |
| 单号 | 工单单号 | 将源工单号写入目标字段 |

- 四个匹配字段须同时成立。编号只去首尾空白，保留前导零、大小写和连字符；需求单号仅按上述末尾两段规则处理，不固定截取字符数，不做模糊匹配、数量合并或四舍五入。
- 例如 `2301-261015010-1-1`、`2301-261015010-10-1`、`2301-261015010-21-1` 均转换为 `2301-261015010`；来源单号主体及两段后缀必须非空，格式不完整时列为异常，不猜补。
- 源文件同一匹配键下的重复 `单号` 只算一个候选；不同 `单号` 均保留。
- **一个目标行、多个候选**：全部工单号按稳定顺序写在同一格，以真实换行分隔。
- **多个目标行、相同四字段**：每行分配一个不同工单号，同一组内不复用。保留已有效且不重复的单工单分配；其余按目标行顺序分配尚未使用的候选。默认按工单号字典序排序，使重跑稳定。
- 重复组的候选数不足时，保留该组现状并列出缺口；不要重复分配、编造或清空已有值。候选多于目标行时列出未分配候选。
- 缺少来源单号、品号或数量、数量无法解析、没有精确匹配时保持现状并说明原因。特征码为空本身不算缺字段。
- 已有工单号不属于本次候选时，保留并列为冲突。不要把覆盖陌生旧值混入普通回填。

## 执行与交付

1. 复用本次已确认的源文件、文档及授权表范围；缺失且无法从上下文确定才询问。源文件只读，计划与输出写本轮新目录，不放入技能目录。
2. 只用[官方钉钉MCP契约](../packing-order/references/dingtalk-mcp.md)完整采集或复用同轮有效快照；缺能力停止并说明。普通表与AI表使用各自身份，不执行浏览器兼容脚本。
3. 按[本技能batch输入](references/batch-run.md)一次prepare全部指定表。原audit负责完整候选、精确计算和分配；主代理验收输入/产物身份、哈希、完整性、表覆盖、关键计数及全部异常，不重复重算成功行。
4. 由主代理按共用MCP契约生成submit-spec、运行一次本地check-before并提交。报告以实际回执为依据；失败/unknown按[停止与恢复](../packing-order/references/performance.md#停止与恢复)，不重放整批。
5. 报告业务行数、实际变更格、重复组及未匹配/冲突/保留原因。不把请求已发出或submitted说成独立持久保存复核。

本地批量委派及接收按[共用分工](../packing-order/references/luna-subagent.md)，正常输出按[执行约定](../packing-order/references/performance.md)。主代理负责正式提交；领料report与提示历史写入也由主代理执行。

## 脚本使用

需要 Python 与 `openpyxl`；Codex 桌面优先通过 `load_workspace_dependencies` 找到已捆绑的 Python，无需为此另装 WPS COM。以 skill 目录内的真实路径调用脚本，不假设当前目录。以下 `python` 表示可用的该解释器。

```text
python scripts/match_workorders.py plan --source 工单.xlsx --target before.tsv --out plan.json
python scripts/match_workorders.py check-before --plan plan.json --snapshot latest.tsv
python scripts/match_workorders.py column-tsv --plan plan.json --out 工单单号.tsv
```

`verify` 命令保留供用户明确要求复核或异常恢复时使用；正常填写流程不运行，也不为它额外采集写后快照。

- 源 XLSX 自动读取有完整源表头的工作表；多表范围不明时用 `--source-sheet` 指定，可重复该参数。目标 XLSX 多表时必须用 `--target-sheet` 指定。TSV/CSV 采用从 `A1` 起的完整矩阵，保留标题、表头、空行及末尾空列。
- 默认在前 20 行找表头；必要时用 `--header-search-rows` 调整。截取范围不是从 `A1` 开始时，在 `plan` 指定 `--target-row-offset`、`--target-column-offset`（从零计）；后续快照保持相同范围。
- `column-tsv` 的输出覆盖计划显示的 `column_range`，并保留这段中每个未改值。它使用标准带引号 TSV，不能按换行简单拆分。若仅局部修改，优先用 `changes` 的单格地址与 `after` 值。
- 快照保存为 UTF-8 TSV。源/目标文件只读；计划及快照放本次工作目录，不放入 skill 安装目录。读表时会校正不可靠的 XLSX dimension，并保留纯零数字格式中的前导零；无法从文件恢复的编号显示格式必须核实，不能自行猜补。
- `check-before` 与 `verify` 的通过条件及差异计数只针对四个匹配列和工单列，范围或列位置变化仍须重新核实。报告里的整表哈希用于保留完整快照的核对线索；其他列被协作更新时，哈希不同本身不表示失败。
