# 每台电脑的独立配置

项目文件更新频繁，由 Git 同步；MCP 配置由每台电脑分别维护。配置不必每次跟随项目更新。

## 首次接入

1. 安装并登录 Codex，打开这个项目的普通本地目录。
2. 按 [E10 MCP 安装包说明](../mcp/README.md)运行仓库内安装脚本；源码、锁定依赖及配置模板已提供。供应商 E10 客户端和 Python 3.12 仍需在本机安装。
3. 在该电脑配置 E10 MCP，使用实际的服务名、解释器、启动参数及集成目录。当前原项目的服务名为 `dingjie-e10-account`；目标电脑可以不同，应以实际工具和配置为准。
4. 安装或连接官方钉钉电子表格 MCP，在该电脑完成账号授权，并确认能访问指定文档。
5. 在每台电脑独立完成 E10 账号配置与认证。现有 E10 使用 Windows 用户 DPAPI 加密凭据，不能将另一台电脑的加密凭据文件直接复制过去使用。
6. 在 Codex 中确认四个项目技能可用。先检查 MCP 是否连接、必要工具和手册是否可读，再开始用户授权的业务；不要用开单或审核测试连接。

## 配置放在哪里

Codex 支持用户级 `~/.codex/config.toml`，也支持受信任项目中的 `.codex/config.toml`。若已有可用的用户级配置，直接沿用；安装脚本按本机路径生成项目级配置，只在本机保存。本项目的 `.gitignore` 已排除 `.codex/`。

跨电脑时各自填写正确路径，不把旧电脑的盘符、用户名或运行环境路径当作通用路径。核实 E10 启动配置时只读取必要的 `command`、`args` 和 `cwd` 字段，不打印整份配置，不读取凭据内容。

配置参考：[Codex 基本配置](https://learn.chatgpt.com/docs/config-file/config-basic)。

## 脚本运行环境

- E10 持续会话助手使用本机 E10 集成环境的 Python 和 MCP 依赖；其运行目录及服务端入口来自本机配置。
- XLSX 匹配助手使用 Codex 提供的工作区 Python；通过 `load_workspace_dependencies` 找到实际路径。不要把表格依赖强行装进 E10 环境。
- JavaScript 回填助手按技能说明，在当前工具环境中加载；需要本地语法检查时使用该电脑可用的 Node.js。
- 当前 E10 接入依赖 Windows。macOS 等系统需要先准备兼容的 E10 服务端或另行接入，单纯克隆仓库不能解决运行环境差异。

## 同名技能

本仓库将四个技能放在 `.agents/skills/`。如果电脑上已有同名个人技能，Codex 可能同时显示多个副本。工作时以本项目路径为准；需要消除重复时，可在该电脑的技能设置中禁用旧副本，不删除其他项目正在使用的文件。

技能发现规则参考：[Codex 技能](https://learn.chatgpt.com/docs/build-skills)。

## 业务记录目录

每轮业务使用本机独立工作目录，例如本项目下被 Git 排除的 `runs/批次名称/`。目录中保留输入、计划、交接、检查点及真实回执。Git 忽略这些文件不等于已有备份；如需跨电脑续办，按[跨电脑使用](跨电脑使用.md)单独交接。
