# 跨电脑使用与更新

## 项目地址

- 私有仓库：[alyssalowo/work-agent-e10](https://github.com/alyssalowo/work-agent-e10)。
- 主分支：`main`。
- 当前电脑正式工作目录：`C:\Users\EDY\Documents\Codex\projects\work-agent-e10`。

在 Codex 中打开正式工作目录使用和更新本项目。原 ChatGPT 项目的镜像目录保留，不作为日常同步目录。GitHub 登录通过浏览器或 Git 客户端完成，不在聊天中发送令牌。

## 另一台电脑首次使用

1. 登录同一个 GitHub 账号，将私有仓库克隆到该电脑的普通工作目录。也可以使用获授权的其他账号。
2. 在 Codex 中打开克隆后的目录，按[本机配置](本机配置.md)独立准备 E10 与钉钉 MCP。
3. 确认项目规则及四个技能已加载，确认必要 MCP 工具可用，再开始新的业务。

可以使用 GitHub Desktop 克隆，或在已安装 Git 的终端中执行：

```text
git clone https://github.com/alyssalowo/work-agent-e10.git
```

克隆项目已包含 MCP 源码、模板和安装步骤；按 [MCP 安装说明](../mcp/README.md)生成本机配置。聊天历史、个人记忆、登录授权及已运行任务不会同步。新电脑仍需具备 ERP 权限、网络和本机运行环境。

## 平时如何更新 agent

- 开始修改前，先拉取远程更新。
- 在当前项目中修改规则、技能或脚本，完成相关检查后提交并推送。
- 另一台电脑使用前拉取更新，重新打开项目或会话，确认使用最新技能。
- 两台电脑尽量不要同时修改同一份规则；存在未提交修改时，先提交或妥善保存，再处理远程变更。

MCP 配置只在接入发生变化时单独维护，无需随每次项目更新重复配置。

## 换电脑继续未完成的业务

1. 先让旧电脑停止该批次的后续操作，保存最新 `context-handoff.md`、用户授权范围、取消项、完整输入和计划、实际操作 ID、检查点及真实回执。
2. 将该批次所需业务记录通过单独的受控方式交接到新电脑的本机工作目录，核对文件完整性及已有哈希。此项目没有建立业务记录自动同步或备份。
3. 在新电脑创建自己的 MCP 连接。旧终端 ID 和连接会话 ID 只作历史证据；业务 operation_id 则保留用于查询执行状态。
4. 先查询未决操作及 E10 实际单据，再从能够证明尚未执行的步骤继续。遇到 unknown、部分成功、缺失回执时不得整批重跑。

原 ChatGPT 项目中的历史业务记录仍留在原处，本次没有搬迁它们。继续原有批次前必须找到对应记录并完成交接。普通 Git 拉取不能替代这一步。

## 文件放置约定

| 内容 | 放置与维护方式 |
| --- | --- |
| 项目规则、技能、脚本、使用文档 | 本项目，Git 提交并推送 |
| MCP 配置、登录信息 | 每台电脑各自配置 |
| E10 MCP 源码、模板及安装脚本 | 仓库 `mcp/`，通过 Git 同步 |
| 虚拟环境、生成配置和供应商 E10 客户端 | 每台电脑本机安装维护 |
| 业务数据、快照、回执、检查点 | 本机业务工作目录，续办时单独交接 |
| 聊天、个人记忆、后台任务 | 不由这个仓库同步 |
