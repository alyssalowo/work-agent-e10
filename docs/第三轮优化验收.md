# 第三轮优化：执行性能与证据校验

日期：2026-10-29。对比基线：`99b3442af0e7d6c16b2567a0ebd98a5ef2406318`。

本轮保留业务规则、第二轮模型分工和权限边界。已实现可选计量及明确重复的本地工作消除；完整包装流程的线上等待和实际 Codex 用量仍需正常授权任务采样，尚不宣称整轮加速。

## 已实现

- `local_evidence.py` 提供默认关闭的数字计量及流式 SHA256。`mcp_session.py --profile-local` 将本地预检、服务就绪、命令阶段的短记录追加到 `local-performance.jsonl`，包括公共助手覆盖的读写、重复读取、哈希、JSON、子进程及 MCP 等待。不记录业务内容、凭据、参数或路径，不增加测速子进程。
- `workorder_branches.py` 在一次连续同步检查内复用已校验文件的字节和解析结果，首次外部等待前释放；重复引用仍逐一比较各自期望值。只需哈希的文件流式处理。独立入口、跨阶段、正式执行和异常恢复的校验继续保留，不按大小、mtime 或旧哈希放行。
- `mcp_session.py` 的命令入口只解析和验证一次；独立调用的公共入口仍自行完成验证。原能力、状态、身份和写入门槛不变。
- Python 公共读写助手接入计量，正式回执仍独占发布并从发布后的实际文件计算哈希。钉钉回执使用宿主提供的单调时钟；宿主缺少 `performance.now()` 时明确记为缺失，业务执行和 unknown 恢复不受可选计时影响。

计量覆盖和使用方式见 [performance.md](../.agents/skills/packing-order/references/performance.md)。各类时间存在包含关系，不能相加；子进程调用全过程与纯启动延迟不能混用。未迁移的内联读写、MCP 服务端和宿主开销不在本地计数中。

## 离线比较

相同合成输入、相同工具模拟响应，每个场景分别运行 15 次，报告中位数。计量和 `tracemalloc` 在两组均开启，文件创建不计入测试，操作系统文件缓存未清空。完整结果见 [round3-benchmark.json](round3-benchmark.json)。

测量范围是统一开单入口至模拟身份检查失败前的连续同步检查。两组都将来源范围检查替换为相同桩，每次仅发生一次模拟身份调用，并确认正式创建器未被调用。因此这不是完整包装流程、真实 ERP/MCP 延迟或真实工具往返的比较。

| 指标 | 小输入：优化前 → 后 | 增加 32 MiB 证据：优化前 → 后 |
| --- | --- | --- |
| 文件读取次数 | 14 → 7 | 16 → 8 |
| 读取字节数 | 2,342 → 730 | 67,111,770 → 33,555,303 |
| 阶段内重复读取字节数 | 1,612 → 0 | 33,556,467 → 0 |
| SHA256 次数 | 9 → 6 | 11 → 7 |
| JSON 解析次数 | 5 → 4 | 5 → 4 |
| 本地耗时中位数 | 5.82 → 5.56 ms | 81.02 → 51.48 ms |
| Python 分配峰值 | 52,958 → 60,347 B | 33,600,593 → 2,152,814 B |
| 模拟工具调用 / 进程启动 | 1 / 0 → 1 / 0 | 1 / 0 → 1 / 0 |

大文件场景的本地耗时下降约 36%，Python 分配峰值约从 32.04 MiB 降至 2.05 MiB。该收益来自本合成路径，不能外推到实际整轮任务。小输入减少了重复工作，但少量额外缓存增加约 7.4 KB Python 峰值，时间差异不足以证明稳定收益。这里的峰值是 Python 分配峰值，不是进程 RSS；没有把摘要字节数换算成 Token 或额度节省。

复现时从上述基线提交导出 `workorder_branches.py` 到仓库外，使用：

```text
python tests/benchmark_round3.py --baseline-script <基线文件绝对路径> --repetitions 15
```

脚本仅使用本地显式提供的基线和合成数据，不下载或运行远程文件，不登录业务系统。
